\section{Contributions, schedule and risks}\label{sec:plan}
This section explains how the outputs of the methodology lead to the expected contributions, and describes the schedule, the division of work, the required resources and the main risks of the study.

\subsection{Expected contributions}\label{sec:contributions}
The study is expected to make three contributions, each of which follows directly from an output of the methodology. First, the reaction points and lags defined in Section~\ref{sec:analysis} quantify, for each diagnostic and for both forms of ray drop, how far the data must degrade before the diagnostic reacts compared with downstream performance. These values answer the main question and provide a comparison that, to our knowledge, is not yet available for FRD, BEV MMD and BEV JSD. Second, the combination of a calibrated baseline, two degradation forms that remove the same expected number of points and thresholds that are fixed in advance (Sections~\ref{sec:data} and~\ref{sec:analysis}) forms a protocol that can be reused for other diagnostics, degradations or datasets. Third, the lags per class and range band obtained under SQ3 show whether the diagnostics react earlier or later than performance in these cases, and thus whether, under the tested conditions, a favourable diagnostic score would have been sufficient grounds for omitting real-data evaluation. Whether an unfavourable score can justify rejecting a dataset version without training a model is a broader decision rule, which this experiment can inform but not establish on its own (Section~\ref{sec:validity}). The outcome remains informative if the hypotheses are refuted, since diagnostics that react in step with performance would support their use as a less costly screening step.

\subsection{Schedule, division of work and resources}\label{sec:schedule}
Figure~\ref{fig:gantt} shows the provisional schedule, which is derived from the tasks in Table~\ref{tab:tasks} and spans nine weeks counted from the start of the study. The weeks will be aligned with the confirmed course milestones. The first two weeks are used for preparation. Both authors define the class mapping and select the synthetic subset, after which Frans Laporte (FL) adapts the LiDARGen code and generates the eleven datasets, while Florent Kegler (FK) sets up the training and evaluation pipeline. In week 3, FL computes the diagnostics for SQ1 and FK trains the baseline models, which fixes the threshold $\delta$. The 30 degraded training runs for SQ2 require both the datasets and this threshold and take up weeks 4 to 6, which makes them the longest task of the study. FL uses this period to write the methods and the SQ1 results. Once all drop points are available in week 7, both authors carry out the comparison for SQ3, while FK writes the SQ2 results. In week 8, both authors write the SQ3 results, the discussion, the abstract and the conclusion, which completes the draft. Week 9 is reserved for applying the feedback of a fellow student and the reviewer and for finalising the report.

The study uses only public data, namely SemanticKITTI and the synthetic dataset, and publicly released code for the diagnostics and the segmentation model, so the main resource is GPU time. The schedule assumes that a single training run takes at most one day on one GPU, so that the 30 degraded runs fit within weeks 4 to 6 when two GPUs are available in parallel. Access to these GPUs is confirmed with the topic contact, Geert Folkertsma, before the study starts, and the assumption is checked during the baseline runs in week 3, as described in Section~\ref{sec:risks}.

\subsection{Risks and mitigations}\label{sec:risks}
Five risks could affect the study, and each is described below together with the measure that limits its effect. The first risk is a low or noisy baseline performance. Models trained exclusively on synthetic data may reach a low mIoU on real data, so that the variation between the three training runs with different random seeds (Section~\ref{sec:model}) becomes large compared with the effect of ray drop. The threshold $\delta$ already accounts for this variation, and additional seeds are trained for the baseline if it remains large. If several small-object classes fall below the minimum baseline IoU of Section~\ref{sec:analysis}, H2 is assessed with the remaining classes and the far-range band, and the excluded classes are reported. If the baseline is too low for any decline to be measured, mixed training with a small and fixed subset of real scans is added as an extension and reported separately, since real training data partly compensates for the degradation.

A second risk is that the 33 training runs require more GPU time than is available. The duration of a single run is therefore measured during the baseline runs in week 3, so that the workload can be adjusted before the degraded runs start. The number of scans or epochs is then reduced equally for all runs, or the number of seeds is reduced to two. If any of these settings changes after the baseline runs, the baseline runs are repeated with the final settings and $\delta$ is recomputed before any degraded run is evaluated. As a last resort, only one form of ray drop is kept, in which case H1 can no longer be tested.

The diagnostics also depend on the reference implementation. FRD depends on the pretrained RangeNet++ weights, and all diagnostics depend on preprocessing that was developed for KITTI-360, so adapting the reference loader could change the behaviour of the diagnostics without this being noticed. To prevent this, the released weights and settings are used unchanged, and the adapted code is checked by computing each diagnostic between two disjoint halves of the real reference set, which should yield values well below those between the synthetic and real sets.

In addition, some synthetic classes may not correspond to a SemanticKITTI class. In that case, the evaluation is restricted to classes that map unambiguously, and the excluded classes are reported. If too few small-object classes remain to test H2, CARLA is used as the alternative source of synthetic data.

Finally, the calibration of the baseline may be unreliable. The fraction of empty pixels may be dominated by rays directed at the sky or at open space, in which case the calibration does not reflect the actual ray-drop rate and low levels of ray drop may move the synthetic data closer to the real data. Because the diagnostic reaction point already detects changes in either direction and performance increases are reported separately from the drop point (Section~\ref{sec:analysis}), such an effect remains visible in the results and is discussed under SQ3 rather than hidden in the lag.

With these measures, the identified risks would mainly reduce the scope or precision of the results rather than prevent the main question from being answered.
