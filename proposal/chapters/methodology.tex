\section{Methodology}\label{sec:method}
This section describes the controlled experiment used to answer the research questions, from the preparation of the data to the analysis of the reaction points and the validity of the resulting conclusions.

\subsection{Experimental design}\label{sec:design}
The study uses a controlled degradation experiment, in which a single synthetic dataset is degraded in steps along one sensor characteristic, ray drop, while the scenes, labels, class mapping, model and training budget are kept fixed. Our literature review argued that differences in sensors, labels and evaluation protocols prevent results from different papers from being pooled, and varying a single factor within one experiment avoids this problem. For every degraded version, the three diagnostics are computed against real scans, and a semantic segmentation model is trained on the degraded data and evaluated on real data. Comparing the degradation level at which performance declines with the level at which each diagnostic reacts answers the main question. Table~\ref{tab:tasks} lists the tasks and outputs associated with each sub-question, which form the basis of the schedule in Section~\ref{sec:schedule}.

\subsection{Data and degradation}\label{sec:data}
The base data is a fixed-size subset of a labelled synthetic dataset such as SynLiDAR~\cite{xiaoTransferLearningSynthetic2022}, with data generated in the CARLA simulator~\cite{dosovitskiyCARLAOpenUrban2017} as an alternative if the class mapping proves problematic. The subset consists of segments of consecutive scans, so that the bootstrap described in Section~\ref{sec:diagnostics} can resample whole segments. The synthetic classes are mapped onto the evaluated classes of SemanticKITTI~\cite{behleySemanticKITTIDatasetSemantic2019}, and classes without a counterpart are ignored. The mapping is documented and identical for all runs.

As noted in Section~\ref{sec:scope}, a basic simulator returns a point for every ray that hits a surface, and LiDARsim reports that real scans typically contain about 10\,\% fewer points than ray-cast versions of the same scenes~\cite{manivasagamLiDARsimRealisticLiDAR2020}. The synthetic scans are therefore expected to contain fewer missing returns than the real scans. Adding a small amount of ray drop could then first reduce the domain gap instead of increasing it, which would conflict with the interpretation of ray drop as a degradation. To limit this effect, the synthetic data is first calibrated to the real data. Both sets are projected to range images, and the average fraction of empty pixels is compared. If the synthetic set contains fewer empty pixels, range-dependent ray drop is applied until both fractions match, since this form most closely resembles the behaviour of a real sensor. If the synthetic set already contains at least as many empty pixels as the real set, no calibration is applied. The resulting set serves as the baseline $d=0$. Empty pixels also arise from rays that do not hit any surface, such as rays directed at the sky, and the calibration matches only the average fraction rather than how missing returns are distributed over range, classes and scenes. It therefore reduces, but does not exclude, the possibility that low levels of additional ray drop move the synthetic data closer to the real data. For this reason, the analysis in Section~\ref{sec:analysis} does not assume that the diagnostics or the performance change monotonically with the degradation level.

Ray drop is then applied to the calibrated point clouds as an additional post-processing step, at levels $d \in \{5, 10, 20, 30, 40\}\,\%$ of the remaining points. Two forms are used, so that the five levels of each form together with the baseline give eleven datasets in total. In the uniform form, every point is removed independently with probability $d$. In the range-dependent form, a point at range $r$ is removed with probability $p(r)=\min(1,\,k\,r)$. The constant $k$ is determined numerically for each level such that the expected fraction of removed points over the dataset equals $d$. The upper bound is required because, without it, the probability for distant points would exceed one at higher levels of $d$. Both forms therefore remove the same expected number of points at a given level and differ only in where these points are removed.

\subsection{Diagnostics}\label{sec:diagnostics}
FRD, BEV MMD and BEV JSD are computed with the publicly released LiDARGen implementation~\cite{zyrianovLearningGenerateRealistic2022}\footnote{\url{https://github.com/vzyrianov/lidargen}} and its default settings. In this implementation, FRD is computed from the bottleneck activations of the pretrained RangeNet++~\cite{miliotoRangeNet++Fast2019}, and both BEV histograms are normalised to sum to one. For BEV JSD, the implementation computes the Jensen--Shannon distance, which is the square root of the divergence, and this value is reported. Because the implementation was written for the KITTI-360 dataset, two adaptations are made. First, the implementation expects its input as range images, so the synthetic point clouds are converted into range images with the same projection settings as the implementation, in which every point removed by ray drop appears as an empty pixel. Second, the part of the implementation that loads the real reference scans is replaced by one that reads a fixed set of SemanticKITTI training scans. All other settings remain unchanged.

Each diagnostic is computed with equal numbers of real and synthetic scans, using the same real reference set for all datasets. The diagnostics are not zero at $d=0$, since a gap between synthetic and real data already exists before any degradation, so only their change relative to $d=0$ is analysed. The uncertainty of this change is estimated with a paired block bootstrap. A bootstrap repeatedly draws a new sample from the available scans, with replacement, and recomputes the diagnostic for each sample, so that the spread of the recomputed values shows how much the result depends on which scans happen to be included. Neighbouring scans in a driving sequence are strongly correlated, so scans are resampled in blocks of 100 consecutive scans rather than individually. In each of 1000 resamples, the same real blocks and the same synthetic blocks are drawn for the baseline and for the degraded dataset, which is possible because every degraded dataset is derived from the same synthetic scans. The 2.5th and 97.5th percentiles of the resampled differences form a 95\,\% interval for the change at each level. These intervals are computed separately for every combination of degradation level, diagnostic and form of ray drop, and are not corrected for multiple comparisons. Since one or two of these 30 intervals are expected to exclude zero by chance alone, a reaction at a single level that is not repeated at higher levels is reported as uncertain rather than as clear evidence.

\subsection{Model, training and outcome measures}\label{sec:model}
One fixed semantic segmentation architecture is trained from scratch on each dataset with the same training budget. Each model is trained three times with a different random seed, which changes the random initialisation of the network and the order in which the training data is presented, so that the variation caused by chance alone can be measured. The planned architecture is MinkowskiNet, a sparse convolutional network that was also used in the SynLiDAR transfer experiments~\cite{xiaoTransferLearningSynthetic2022}, which makes the baseline comparable with published results. It operates on voxelised point clouds rather than on range images and thus differs from RangeNet++, so that the network used by FRD is independent of the model whose performance is measured. The size of the subset and the number of epochs are set during the baseline runs such that a single run fits the compute budget described in Section~\ref{sec:schedule}, and they are then fixed for all runs. Training uses synthetic data only. No real labels are used for training or for checkpoint selection, and the model after the final epoch is evaluated. This avoids the optimistic bias that arises when checkpoints are selected on real data, as discussed in our literature review.

Evaluation uses SemanticKITTI sequence 08, which is not used for any other purpose in the study. Performance is reported as the overall mIoU over the classes retained by the class mapping, as the IoU of each of these classes, and as the mIoU within the range bands 0--20\,m, 20--40\,m and more than 40\,m. Within a band, the IoU of a class is computed from the points in that band only. A class without any labelled or predicted point in a band has no defined IoU there and is left out of the average for that band rather than counted as zero. These measures provide the outcomes needed for SQ2 and for the class- and range-specific comparisons in SQ3.

\subsection{Analysis}\label{sec:analysis}
Reaction points are determined separately for each form of degradation. The performance drop point $d_P$ is the lowest degradation level at which the mean of a performance measure over the seeds lies at least $\delta$ below its value at $d=0$, expressed as a relative decrease. It is determined for the overall mIoU, for the IoU of each class and for the mIoU of each range band. The threshold is set to $\delta=\max(5\,\%,\,2\times\mathrm{CV}_0)$, where $\mathrm{CV}_0$ is the coefficient of variation of the corresponding measure across the seeds at $d=0$, and it is fixed before any degraded run is evaluated. With three seeds, this rule is an operational threshold that makes it unlikely that ordinary variation between seeds is read as a decline, but it does not guarantee this. Because a relative decrease is not meaningful for a value close to zero, classes with a baseline IoU below five percentage points are reported but receive no drop point. The diagnostic reaction point $d_M$ is the lowest degradation level at which the 95\,\% interval of the change relative to $d=0$ (Section~\ref{sec:diagnostics}) excludes zero.

Neither the diagnostics nor the performance measures are assumed to change monotonically. A diagnostic reaction counts in either direction, since a diagnostic that moves towards the real data still registers the ray drop, and its direction is always reported, because a diagnostic that improves while performance declines would be misleading in practice. For performance, only a decline defines $d_P$, and levels at which performance increases are reported separately. In both cases the first crossing defines the reaction point, and any later return within the normal variation is reported. A reaction point that is not reached within the tested range is recorded as lying above 40\,\%.

The lag $\Delta=d_M-d_P$ is positive when a diagnostic reacts later than performance, which corresponds to a missed degradation, and negative when it reacts earlier, which corresponds to a false alarm. Because the grid contains only five non-zero levels, each reaction point is localised to an interval between two levels, and reaction points that fall in the same interval are treated as equal. When only one of the two points is reached, the lag is reported as a bound, for instance as a missed degradation with a lag of more than $40\,\%-d_P$. When neither point is reached, no lag is assigned. If time allows, the grid is refined around the observed reaction points. H1 is evaluated by comparing $d_M$ for each diagnostic between the two forms of ray drop, H2 by comparing $d_P$ of the small-object classes and of the far-range band with $d_P$ of the overall mIoU, and H3 through the sign of $\Delta$ for each diagnostic, following the criteria in Section~\ref{sec:hypotheses}. The Spearman rank correlation between each diagnostic and the mIoU is reported as supporting information only. With so few levels, these correlations and the per-class results are descriptive and are not treated as independent statistical evidence.

\subsection{Validity}\label{sec:validity}
The internal validity of the study rests on varying a single factor while keeping all others fixed. Seeds, class mapping, preprocessing, model, training budget and code are recorded in the shared repository, and the threshold $\delta$ and the analysis plan are fixed before the degraded runs are evaluated. The real scans are separated by purpose, as the training sequences of SemanticKITTI serve only as the reference set for the diagnostics and sequence 08 serves only for evaluation, so that no real scan contributes to both. The synthetic training data comes from a different source entirely and shares no scenes with either set.

Construct validity concerns whether the measurements capture what they are intended to capture. Using the released diagnostic implementation with only the necessary adaptations keeps the diagnostics comparable to their use in the literature. Choosing a segmentation model other than RangeNet++ prevents FRD from being favoured by sharing its feature extractor with the evaluated model.

The conclusions are limited to the chosen architecture, to a single sensor type and to two forms of ray drop in a synthetic-only training setting, and are not claimed to generalise to other degradations, tasks or training regimes. A reaction pattern observed in this setting would therefore have to be confirmed on other datasets, models and degradations before a diagnostic score could serve as a general rule for accepting or rejecting synthetic datasets. The calibration of the baseline is based on the fraction of empty pixels, which only approximates the real ray-drop rate. Within these limits, the design allows the reaction points of the diagnostics and of downstream performance to be compared directly, which is the comparison required to answer the main question.
