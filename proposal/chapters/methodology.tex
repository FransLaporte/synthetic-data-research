\section{Methodology}\label{sec:method}
This section describes the controlled experiment used to answer the research questions, from the preparation of the data to the analysis of the reaction points and the validity of the resulting conclusions.

\subsection{Experimental design}\label{sec:design}
The study uses a controlled degradation experiment, in which a single synthetic dataset is degraded in steps along one sensor characteristic, ray drop, while the scenes, labels, class mapping, model and training budget are kept fixed. For every degraded version, the three diagnostics are computed against real scans, and a segmentation model is trained whose performance on real data is then measured. Comparing the degradation level at which the mIoU declines with the level at which each diagnostic reacts answers the main question. Our literature review argued that differences in sensors, labels and evaluation protocols prevent results from different papers from being pooled, and varying a single factor within one experiment avoids this problem. \subsection{Data and degradation}\label{sec:data}
The base data is a fixed-size subset of a labelled synthetic dataset such as SynLiDAR~\cite{xiaoTransferLearningSynthetic2022}, with CARLA as an alternative if the class mapping proves problematic. The synthetic classes are mapped onto the evaluated classes of SemanticKITTI~\cite{behleySemanticKITTIDatasetSemantic2019a}, and classes without a counterpart are ignored. The mapping is documented and identical for all runs.

As noted in Section~\ref{sec:scope}, a basic simulator returns a point for every ray that hits a surface, and LiDARsim reports that real scans typically contain about 10\,\% fewer points than ray-cast versions of the same scenes~\cite{manivasagamLiDARsimRealisticLiDAR2020a}. The synthetic scans are therefore expected to contain fewer missing returns than the real scans. Adding a small amount of ray drop could therefore first reduce the domain gap instead of increasing it, which would conflict with the interpretation of ray drop as a degradation. To avoid this, the synthetic data is first calibrated to the real data. Both sets are projected to range images, and the average fraction of empty pixels is compared. If the synthetic set contains fewer empty pixels, range-dependent ray drop is applied until both fractions match, since this form most closely resembles the behaviour of a real sensor. Empty pixels also arise from rays that do not hit any surface, such as rays directed at the sky, so this comparison provides an estimate rather than an exact ray-drop rate. The calibrated set serves as the baseline $d=0$, so that every further level moves the synthetic data away from the real data. If the synthetic set already contains at least as many empty pixels as the real set, no calibration is applied.

Ray drop is then applied to the calibrated point clouds as an additional post-processing step, at levels $d \in \{5, 10, 20, 30, 40\}\,\%$ of the remaining points. Two forms are used, which together with the baseline results in eleven datasets in total. In the uniform form, every point is removed independently with probability $d$. In the range-dependent form, a point at range $r$ is removed with probability $p(r)=\min(1,\,k\,r)$. The constant $k$ is determined numerically for each level such that the expected fraction of removed points over the dataset equals $d$. The upper bound is required because, without it, the probability for distant points would exceed one at higher levels of $d$. Both forms therefore remove the same expected number of points at a given level and differ only in where these points are removed.

\subsection{Diagnostics}\label{sec:diagnostics}
FRD, BEV MMD and BEV JSD are computed with the released LiDARGen implementation~\cite{zyrianovLearningGenerateRealistic2022}\footnote{\url{https://github.com/vzyrianov/lidargen}} and its default settings. In this implementation, FRD is computed from the bottleneck activations of the pretrained RangeNet++~\cite{miliotoRangeNet++Fast2019a}, BEV MMD uses a Gaussian kernel, and both BEV histograms are normalised to sum to one. The implementation computes the Jensen--Shannon distance, which is the square root of the divergence, and this value is reported. Because the released code expects range images and uses KITTI-360 as its reference, two adaptations are made. The synthetic point clouds are projected to range images with the projection parameters used by the implementation, so that removed points appear as empty pixels. The reference loader is replaced by one that reads a fixed set of SemanticKITTI training scans. All other settings remain unchanged.

Each diagnostic is computed with equal numbers of real and synthetic scans. To estimate its normal variation, 1000 bootstrap resamples of the scans are drawn for every dataset, which yields a 95\,\% interval per value. The diagnostics are not zero at $d=0$, since a gap between synthetic and real data already exists before any degradation. Only their change relative to $d=0$ is therefore analysed.

\subsection{Model, training and outcome measures}\label{sec:model}
One fixed segmentation architecture is trained from scratch on each dataset with the same training budget and a fixed number of epochs, using three random seeds. The final choice of architecture depends on the available compute, but it differs from RangeNet++ so that the network used by FRD is independent of the model whose performance is measured. Training uses synthetic data only. No real labels are used for training or for checkpoint selection, and the model after the final epoch is evaluated. This avoids the optimistic bias that arises when checkpoints are selected on real data, as discussed in our literature review.

Evaluation uses SemanticKITTI sequence 08, which is not used for any other purpose in the study. The mIoU is reported overall, per class and per range band, with bands of 0--20\,m, 20--40\,m and more than 40\,m. These measures provide the outcomes needed for SQ2 and for the class- and range-specific comparisons in SQ3.

\subsection{Analysis}\label{sec:analysis}
Two reaction points are determined for each form of degradation. The mIoU drop point $d_P$ is the lowest degradation level at which the mean mIoU over seeds is at least $\delta$ below its value at $d=0$, expressed as a relative decrease. It is determined for the overall mIoU, for each class and for each range band. The threshold $\delta$ is fixed before any degraded run is evaluated and is set to $\delta=\max(5\,\%,\,2\times\mathrm{CV}_0)$, where $\mathrm{CV}_0$ is the coefficient of variation of the corresponding mIoU across seeds at $d=0$. This prevents normal variation between seeds from being interpreted as a decline. The diagnostic reaction point $d_M$ is the lowest degradation level at which the value of a diagnostic lies outside the 95\,\% bootstrap interval of its value at $d=0$.

The lag $\Delta=d_M-d_P$ is positive when a diagnostic reacts later than the mIoU, which corresponds to a missed degradation, and negative when it reacts earlier, which corresponds to a false alarm. Because the grid contains only five non-zero levels, each reaction point is localised to an interval between two levels, and reaction points that fall in the same interval are treated as equal. If time allows, the grid is refined around the observed reaction points. H1 is then evaluated by comparing $d_M$ for each diagnostic between the two forms of ray drop. H2 is evaluated by comparing $d_P$ for small classes and the far-range band with $d_P$ for the overall mIoU. H3 is evaluated through the sign and size of $\Delta$ for each diagnostic. The Spearman rank correlation between each diagnostic and the mIoU is reported as supporting information only. With so few levels, these correlations and the per-class results are descriptive and are not treated as independent statistical evidence.

\subsection{Validity}\label{sec:validity}
The internal validity of the study rests on varying a single factor while keeping all others fixed. Seeds, class mapping, preprocessing, model, training budget and code are recorded in the shared repository, and the threshold $\delta$ and the analysis plan are fixed before the degraded runs are evaluated. The real scans are separated by purpose, as the training sequences of SemanticKITTI serve only as the reference set for the diagnostics and sequence 08 serves only for evaluation, so that no real scan contributes to both. The synthetic training data comes from a different source entirely and shares no scenes with either set.

Construct validity concerns whether the measurements capture what they are intended to capture. Using the released diagnostic implementation with only the necessary adaptations keeps the diagnostics comparable to their use in the literature. Choosing a segmentation model other than RangeNet++ prevents FRD from being favoured by sharing its feature extractor with the evaluated model.

The conclusions are limited to the chosen architecture, to a single sensor type and to two forms of ray drop in a synthetic-only training setting, and are not claimed to generalise to other degradations, tasks or training regimes. The calibration of the baseline is based on the fraction of empty pixels, which only approximates the real ray-drop rate. Within these limits, the design allows the reaction points of the diagnostics and of downstream performance to be compared directly, which is the comparison required to answer the main question.
